# Mine V2 Implementation Plan

> **For Codex:** Use `superpowers:executing-plans` to implement this plan task-by-task in the current worktree. Do not delegate this execution; steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the legacy mining controller with a prospection, mining, loading and routed extraction expedition plus all eight specified incidents.

**Architecture:** `MineComponentGraph` wires focused owners into `MineModule`. The existing atomic block recovery journal is migrated intact. Common objective, guidance, service-item and safety mechanics control targets and participants while mine-specific owners control blocks, entities, routes and story rules.

**Tech Stack:** Kotlin 2.3.0, Java 25, Paper/Purpur 1.21.11, MockBukkit, Kotest, MockK, chunk PDC, existing `MineRecoveryJournal`.

**Spec:** `docs/superpowers/specs/2026-08-30-worksite-v2-design.md`

## Global Constraints

- Complete the worksite kernel plan first; the lumber plan may run before or after this plan.
- Preserve mine button, destinations, permissions, activity kind, weighted rewards and every pending recovery record.
- Every destructive block mutation follows durable journal success.
- Decorative carts use grounded `ItemDisplay`/`Interaction`, not `Minecart`.
- Generated targets request twice the quota; hot ticks use durable indexes and loaded chunks.
- Every player-facing message is mirrored in RU/EN.
