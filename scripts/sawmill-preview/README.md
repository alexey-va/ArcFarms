# Кедровый двор: закрытая beta лесоруба

В мире `rc_atelier_cedar_sawmill` работает одна общая заготовка: настоящее
дерево из существующего леса → рубка → падение → три ветви → поводок →
уличная приёмная зона → круговая пила → два распила → тележка → склад внутри цеха.
Участие, инструменты, подсказки, маски дерева, обработка кликов и пакетные
дисплеи требуют `arcfarms.lumber.beta` (default false). Без права модуль
пропускает события и оставляет обычный мир. Для ПКМ пустой рукой
`PaperSpatialControls` создаёт скрытые по умолчанию `Interaction`, видимые
только текущей beta-аудитории. Шесть малых целей покрывают весь ствол.
Перед действием контроллер заново проверяет луч и права; рубка топором
сохраняет прежний квалифицированный внешний ввод. Станок изначально пуст и не создаёт новое бревно по рычагу.

Станок развернут на 180°; начало display-композиции —
`[188.429,73,178.8]`, масштаб — прежний `1.7`. Ось рельсов проходит по
`X189.5` между существующими колоннами `X186` и `X192`. Наружный конец —
`Z200.56`, шпалы занимают `X187.885..191.115`. Пульт перенесён на восток:
ручка рычага находится в `[192.5,74.785,176.964]`, подход — со стороны `X194`.
Выдача расположена на той же стороне, центр штабеля — `[192.084,75.9325,172.68]`.
Никакие блоки здания или улицы не меняются.

Перед входом обозначен золотой квадрат 6×6 м: `X186.5..192.5`,
`Z196.5..202.5`, пол `Y73`. Игроку с бревном достаточно войти в квадрат;
ориентация и положение самого бревна не ограничивают сдачу. Замороженная
фактическая поза груза становится первым кадром шестисекундного переноса:
выравнивание снаружи, подъём, продольная затяжка по центру двери, боковое
размещение на каретке. Ствол проходит дверной проём в `X188.684..190.316`,
обходит подвесной фонарь и только после выхода хвоста из двери смещается
к точной подаче `[188.429,75.771,188.66]`.

Свободный ствол подсвечен; ПКМ по всей его длине сразу берёт его на поводок.
Нативный невидимый якорь и настоящий vanilla leash используют
`WorksiteCrankTethers`; private-якорь скрыт до начала tracking и показывается
только beta-аудитории текущего круга. Сырое бревно перевозится без телеги.
Игрок идёт впереди, бревно подтягивается за ним при расстоянии свыше 5.25 м.
Поворот камеры сам по себе не таскает груз вокруг игрока. Проверки прохода
бревна через блоки отключены по запросу владельца; карта при этом неизменна.
Движение игрока замедлено только на время владения бревном.

Время задаёт общий `LumberTiming`: падение 60 ticks, затяжка на станок
120 ticks, каждый распил 240 ticks (12 секунд), загрузка досок на тележку 40 ticks.
Рычаг после прохода выключен; второй проход требует отдельного нажатия.
После сбора станок снова пуст. Подсвечено только доступное следующее действие:
выбранный ствол, свободное бревно, готовый рычаг или готовые доски. Работающий
станок не предлагает повторный клик. Подсказка содержит ближайшее действие
и один способ ввода; title и subtitle хранятся отдельными строками.

Тележка ожидает у восточной выдачи в `[194.6,73,172.68]`. Все пятнадцать
деталей готового штабеля сначала сдвигаются над столом, затем опускаются
на тележку. Опоры находятся на `Y73.10`, верх груза по точным native-границам —
`Y74.494`, ниже уровня глаз. Плоский настил расположен между боковыми колёсами.
После завершения загрузки игрок толкает тележку впереди себя по восточному
проходу к отметке `[194.1,73,185.5]`. После сохранения сдачи короткая анимация
за одну секунду укладывает тот же штабель на две деревянные опоры.
Показательный складской штабель не является новой системой учёта.
Кран и перевозка через реку остаются будущим отдельным этапом.
Beta считает только завершённые круги;
денег, предметных наград и XP нет.

Исходные блоки дерева выше двухблочного пня скрываются только участникам.
Падающая копия использует захваченные BlockData, затем три отдельные ветви
снимаются физическими действиями. Один ствол длиной 7.48 м остаётся той же
заготовкой на каждом переходе. При подборе квадратный профиль
захваченного дуба стилизуется под существующую округлую модель сырья с её
прежними еловыми текстурами. Это явное приближение закрытой beta, а не новая
порода древесины, материал награды или новый asset.

Валка вращает деревянные кубы вокруг передней кромки среза 44 ticks,
затем за 16 ticks опускает их рядом с сохранённым пнём. Индекс проверяет
не условную широкую полосу, а swept bounds этих LOG-кубов на 61 позе,
включая угловые экстремумы между ticks. Грунт, пень, чужие стволы,
сооружения и неизвестные клетки блокируют выбор направления.
Только при декоративной виртуальной валке допускается проход сквозь
соседнюю листву: она не маскируется и не меняется. У дерева `[139,73,202]`
при падении на север это семь OAK_LEAVES: `[139,82,200]`, `[139,83,200]`,
`[139,76,200]`, `[139,77,200]`, `[139,76,199]`, `[139,77,199]`, `[139,76,198]`.
Это ограниченное приближение beta. Валка сохраняет собственные проверки;
переноска на поводке не проверяет блоки и не редактирует их.

Пять моделей `arc_farms:cedar_sawmill_{raw,sawn,slab,blade,pulley}` и их
PAPER CMD `271001..271005` сохранены побайтно. Пакет не дополняется.
Ветви, дерево, приёмная разметка и временный такелаж используют vanilla
BlockDisplay. Машина содержит 127 деталей, включая 23 ItemDisplay.
Переносимый штабель сохраняет все пятнадцать выходных деталей и их масштаб.

## Источники

- `src/main/resources/sawmill/cedar-machine.json` — исходная геометрия,
  единственный поворот display-композиции, опоры и пять native-моделей.
- `CedarSawmillGeometry`, `CedarSawmillAnimation` — канонические позы обоих
  проходов; `CedarSawmillController` показывает состояние общей заготовки.
- `LumberSceneGeometry` — падение, три цели ветвей, подсвеченный подбор,
  приёмная зона, тележка и складской штабель. Доски не прикрепляются к игроку.
- `LumberSceneExport` — один полный круг реального `LumberEngine` с позами
  из тех же функций, 10 кадров в секунду. Путь игрока задаётся входной fixture;
  `LumberLogMotion` рассчитывает положение следующего за ним бревна;
  общий с действующими работами `WorksiteCartMotion` ведёт тележку впереди игрока.
- `lumber-tree.snapshot.json` — фактический ствол `[139,73,202]`, направление
  на север, его блоки, старт груза, склад и постановочный путь игрока.
- `lumber-area.snapshot.json` — 18 200 блоков района из capture 25 октября;
  `room.snapshot.json` сохраняет прежний ограниченный снимок цеха.
  `lumber-live-readback.json` отдельно фиксирует подтверждённые чтением AIR
  поверх этого снимка. Остальные клетки сохраняют захваченное состояние.
  Снимки не доказывают актуальное состояние живого мира после этой даты.

Сдача находится внутри цеха в `[194.1,73,185.5]`, на существующем деревянном
полу восточного прохода. Двенадцать AIR-клеток у нового пульта и маршрута
подтверждены отдельным текущим readback (`artifacts/lumber-ux-20261026/loaded-readback.json`);
остальные пространственные проверки используют сохранённый capture. Внешний
двор со штабелями и краном не является целью этого рабочего круга.
Начальная пешая точка у существующей тропы — `[144.5,73,206.5]`.

## Проверка и просмотр

Из корня ArcFarms, с Java 25:

```sh
./gradlew validateCedarSawmill
python3 scripts/sawmill-preview/ground-native-models.py --client-jar /absolute/path/to/minecraft-1.21.11-client.jar
python3 scripts/sawmill-preview/ground-lumber-stock.py
python3 scripts/sawmill-preview/ground-board-cart.py
node scripts/sawmill-preview/check.mjs
node scripts/sawmill-preview/build.mjs --atelier=/absolute/path/to/location-atelier --client-jar=/absolute/path/to/minecraft-1.21.11-client.jar
python3 -m http.server 8853 --bind 127.0.0.1 --directory build/reports/sawmill-preview
```

`http://127.0.0.1:8853/?mode=lumber&view=forest&t=0` показывает полный круг.
Есть пауза, 1× playback, выбор этапа и ракурса. «Игрок · вперёд» и
«Игрок · оглянуться» показывают свободный передний обзор и расстояние до
бревна сзади. «Игрок · тележка» показывает груз впереди игрока и короткий путь
к складу в цеху. Человеческая фигура и изгиб верёвки в browser схематичны;
золотая подсветка материала показывает состояние нативного glow. `beta=0` показывает второго
зрителя без private-дисплеев и без маски дерева. Это проверка визуального
контракта; проверка permission на сервере остаётся отдельной.

Без `mode=lumber` доступны прежние детальные ракурсы машины, `pass=0|1`,
`t=0..25` и промежуточные позы. Это инспектор анимации двух проходов, а не
описание бесконечной генерации сырья на сервере. Канонический 25-секундный
параметр анимации отображается в runtime на 12 секунд каждого прохода.

Manifest связывает compiled-классы, экспорт и SHA пяти неизменных моделей.
Grounding отчёты проверяют точные ItemDisplay `NONE`, native Y180, quaternion,
масштаб и контакты с опорами; остаток должен быть не выше `1e-4` блока.
`ground-lumber-stock.py` отдельно проверяет пол под новыми
положениями сырья; `ground-board-cart.py` проверяет контакты досок на тележке
и складе, а также весь короткий путь по полным клеткам capture. Временная allocation fixture служит только анализатору и
не меняет ItemsAdder cache. Browser использует настоящие PNG, UV и грани.

`preview-mask.json` описывает прежний декор, скрываемый только в отдельном
инспекторе машины для сравнения. Полный круг `mode=lumber` этот mask не
применяет: он и collision fixture используют один capture с подтверждённым
readback overlay. `.schem` для импорта не
сохраняется. Динамические block-entity модели вроде горшков и медных сундуков
имеют обозначенные renderer fallback; не влияющие на модель свойства
нормализованы только в recipe просмотра. Runtime BlockData остаются точными.

Сборка, canonical export, offline grounding, rendered browser и нативный
клиент — разные уровни проверки. Плавность движения тележки, реальное
ощущение поводка, пакетная приватность и звук в Minecraft требуют проверки
после активации. Обновление кода активируется штатным рестартом сервера;
сама сцена не меняет мир и не обновляет resource pack.
